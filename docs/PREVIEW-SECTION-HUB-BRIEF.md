# تقرير استشاري — تجربة أقسام ERVENOW (الرئيسية + صفحات الأقسام)

**التاريخ:** 7 يونيو 2026  
**الحالة:** معاينة معتمدة مبدئياً من صاحب المشروع — **لم يُطبَّق بعد** على الصفحات الحقيقية  
**الغرض:** مشاركة مع شريك النجاح / ChatGPT لاتخاذ قرار تنفيذ موحّد

---

## 1. الملخص التنفيذي

بعد مراجعة الصفحة الرئيسية ولوحة الزائر وإدارة البنرات، تم الاتفاق مبدئياً على **نموذج تنقّل جديد** لأقسام المنصة الأربعة:

| القسم | السلوك المقترح |
|-------|----------------|
| مطاعم | نقر من الرئيسية → صفحة `/restaurants` |
| متاجر | نقر من الرئيسية → صفحة `/stores` |
| توصيل | نقر من الرئيسية → صفحة `/delivery-services.html` |
| خدمات | نقر من الرئيسية → صفحة `/services` |

**بدلاً من:** فتح قائمة منسدلة داخل بطاقة الرئيسية (`<details>`).  
**إلى:** صفحة قسم مستقلة فيها **تصنيفات فرعية أعلى** + **قائمة نتائج تحت** + **أزرار ترتيب**.

---

## 2. ما تم رفضه / لم يعجب

1. **القائمة المنسدلة في الرئيسية** — ضيقة على الجوال، خاصة لكبار السن، وفيها خيارات كثيرة (المطاعم ~10 تصنيفات).
2. **معاينة «صفحة فرعية داخل المعاينة»** (`/preview/home-hub-direct.html`) — لم تكن بالشكل المطلوب؛ المطلوب صفحة كاملة وليس محاكاة داخل صفحة واحدة.
3. **إجبار المستخدم على اختيار تصنيف قبل عرض النتائج** — في `/restaurants` الحالية يظهر أحياناً «اختر تصنيف المطبخ» بدون عرض المطاعم؛ المطلوب **عرض الكل افتراضياً**.

---

## 3. ما تم اعتماده (المعاينة الأخيرة)

صاحب المشروع أعجبته معاينات الأقسام الأربعة على الروابط:

| القسم | معاينة |
|-------|--------|
| فهرس | http://localhost:4000/preview/ |
| مطاعم | http://localhost:4000/preview/restaurants-hub.html |
| متاجر | http://localhost:4000/preview/stores-hub.html |
| توصيل | http://localhost:4000/preview/delivery-hub.html |
| خدمات | http://localhost:4000/preview/services-hub.html |

### عناصر كل صفحة قسم (موحّدة)

```
┌─────────────────────────────────────────────┐
│  هيدر القسم (عنوان + وصف قصير)              │
├─────────────────────────────────────────────┤
│  🔍 بحث بالاسم                               │
│  [ الأقرب ] [ الأعلى تقييماً ] [ عروض ]      │
├─────────────────────────────────────────────┤
│  تصنيفات فرعية (شريط أفقي — «الكل» + باقي)   │
├─────────────────────────────────────────────┤
│  عداد النتائج + وصف الفلتر النشط             │
├─────────────────────────────────────────────┤
│  شبكة بطاقات (مطاعم / متاجر / خدمات…)        │
└─────────────────────────────────────────────┘
```

### قواعد السلوك

- **بدون اختيار تصنيف فرعي** → تظهر **كل** النتائج المعتمدة للقسم.
- **اختيار تصنيف** → تصفية القائمة تحته فوراً.
- **الأقرب** → ترتيب بالمسافة (يتطلب موقع المستخدم أو تفعيل فلتر الموقع).
- **الأعلى تقييماً** → `average_rating` من API.
- **عروض** → عناصر/متاجر/مزودون لديهم **خصومات تشغيلية فعلية** (منتج أو خدمة أو عرض شامل) — **ليس** بنرات `platform-offers`. مرجع: `docs/OFFERS-OPERATIONAL-SPEC.md`.
- **بحث** → بالاسم ضمن النتائج المفلترة حالياً.
- أزرار اللمس **≥ 44px** — مناسبة لجوال وكبار السن وتابلت.

- تحويل بطاقات `#snHomeHub` من `<details>` + قائمة منسدلة إلى **روابط مباشرة** للصفحات أعلاه.
- إزالة تكرار التصنيفات الفرعية من الرئيسية — مصدر واحد في صفحة كل قسم.

## 5. التصنيفات الفرعية لكل قسم

### مطاعم (`/restaurants?category=...`)

كبسة وبخاري · شاورما ومشاوي · سمك · برقر · بروستد · بيتزا · مقاهي · حلويات · أسر منتجة · **الكل**

### متاجر (`/stores?type=...`)

سوبر ماركت · صيدليات · خضار · ورود وهدايا · حلويات · أسر منتجة · **الكل**

### توصيل (`/delivery-services.html?service=...`)

نقل مركبات · توصيل داخلي · نقل أثاث · توصيل غاز · طلب من الخريطة · **الكل**

### خدمات (`/services?type=...`)

سباك · كهربائي · مشتل · فني مكيفات · غسيل درج فيلا · غسيل درج عمارة · **الكل**

## 6. الوضع التقني الحالي في المشروع

| العنصر | موجود | ملاحظة |
|--------|--------|--------|
| صفحات `/restaurants` `/stores` `/services` | ✅ | تحتاج توحيد UX مع المعاينة |
| API `GET /api/stores` | ✅ | يدعم `type`, `category`, `user_lat/lng`, `sort=rating` |
| ترتيب «الأقرب» | جزئي | عند إرسال إحداثيات المستخدم |
| ترتيب «عروض» | ⚠️ | `offer_price` على المنتج موجود؛ عروض % وشاملة وخدمات — مرحلة لاحقة |
| الرئيسية — قوائم منسدلة | ✅ حالياً | **مطلوب تغييره** عند القرار النهائي |
| معاينات `/preview/*` | ✅ | بيانات تجريبية فقط |

### إصلاحات أخرى تمت في الجلسة (منفصلة عن هذا التقرير)

- لوحة الزائر: إزالة بطاقة «أنت تتصفّح كزائر»، ضبط بطاقة الترحيب والبنر.
- الرئيسية: بنر شرائح موحّد مع لوحة الزائر.
- إدارة البنرات: إيقاف إعادة التحميل المتكرر وفقدان التصفية.

## 7. خطة تنفيذ مقترحة (بعد موافقة الشريك)

### المرحلة 1 — المطاعم (نموذج مرجعي)

1. تعديل `/restaurants`: عرض الكل افتراضياً، شريط تصنيفات، أزرار ترتيب، بحث.
2. ربط `sort` و`category` بـ API.
3. اختبار جوال 320px / تابلت 768px / سطح مكتب 1280px.

### المرحلة 2 — نسخ النمط

4. `/stores` بنفس الهيكل.
5. `/services` بنفس الهيكل.
6. `/delivery-services.html` بنفس الهيكل.

### المرحلة 3 — الرئيسية

7. بطاقات الأقسام الأربعة → روابط مباشرة فقط.
8. إزالة `<details>` والقوائم المكررة.

### المرحلة 4 — عروض (إن وُجدت في المنتج)

9. تعريف «عرض نشط» في API أو فلتر client-side.
10. زر «عروض» يفعّل الفلتر.

---

## 8. أسئلة للمشاورة مع شريك النجاح

1. هل نُبقي **اختصارات سريعة** (2–3 تصنيفات) تحت بطاقات الرئيسية أم الاكتفاء بأربع بطاقات فقط؟
2. ~~هل زر «عروض» يعرض خصم أم بنر؟~~ **مُحسَم:** خصم تشغيلي فقط — انظر `OFFERS-OPERATIONAL-SPEC.md`.
3. هل **«الأقرب»** يطلب إذن الموقع تلقائياً أم يعتمد على checkbox «قرب موقعي» كما في الصفحة الحالية؟
4. هل صفحة التوصيل تبقى `/delivery-services.html` أم نُوحّد المسار إلى `/delivery`؟
5. أولوية الإطلاق: **الأربعة معاً** أم **مطاعم أولاً** ثم الباقي؟

```
- http://localhost:4000/preview/

(2) ترتيب الأولويات للتنفيذ (3) أفضل ممارسة لزر «عروض»
(4) هل نحتاج اختصارات في الرئيسية أم أربع بطاقات فقط؟
```
