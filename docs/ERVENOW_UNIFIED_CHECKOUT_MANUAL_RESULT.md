## `/my-orders`

بعد كل إنشاء ناجح: `GET /my-orders` ثم `GET /api/order/orders` = 200 لنفس `customer_id`. قائمة الطلبات تُفلتر بـ `customer_id` حتى لو كان `role=store`، وحجم الاستجابة كبر بعد الطلب الثاني. الظهور في الصفحة يطابق السجلات.

## هل رحلة العميل جاهزة تقنيًا لتفعيل PUBLIC_ORDERING؟

**لا — ليس لتفعيل الإنتاج / `.env`.**

ما ثبت يدويًا: مطعم واحد → OTP على رقم موجود → Order واحدة بـ `customer_id` صحيح → تظهر عبر `/api/order/orders` في `/my-orders` → تصل لتاجر كبسار + أدمن → لا Ledger نقدًا → لا INSERT قبل OTP.

ما لم يثبت ولا يكفي لفتح القفل:

1. عميل جديد (Customer تلقائي) — المختبِر `role=store`.
2. Fulfillment Groups متعددة في تأكيد واحد.
3. كتالوج غير المطعم (صيدلية / متجر / نقل) كـ Orders حية.
4. ERVENOW PAY وحركة دفتر.
5. Redis/طابور غير جاهزين محليًا.
6. Dispatch / Settlement / Unified Actions خارج هذا الاختبار عمدًا.
7. `.env` و`data/public-ordering.json` ما زالا `false` — هذا القفل الإنتاجي.

التفعيل المحلي في عملية الخادم كان للاختبار فقط ولم يُكتب في الملفات.
