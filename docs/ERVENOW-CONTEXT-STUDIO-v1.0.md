## الغرض

**Context Studio** هو محرك السياق — ليس محرك العرض.

بينما **Marketing Studio** يقرر *أين ومتى* تظهر الوحدات، يقرر **Context Studio** *لماذا هذه الرسالة الآن* بناءً على:

| إشارة سياق | أمثلة |
|------------|--------|
| **الوقت** | صباح · غداء · مساء · ليل |
| **الطقس** | حر · برد · مطر |
| **المناسبة** | رمضان · عيد · وطني · دراسة · weekend |
| **المدينة** | استهداف محلي |
| **نوع المستخدم** | ضيف · مسجّل · شريك |

---

## المبادئ (من EHX + Vision 2030)

1. **لا رسالة بدون تفسير** — يجب أن نستطيع الإجابة: «لماذا ظهرت لهذا المستخدم؟»
2. **رسالة واحدة · قصيرة · غير مزعجة**
3. **الخصوصية أولاً** — موافقة المستخدم والإعدادات
4. **لا نصوص ثابتة في الكود** — كل القواعد والرسائل من لوحة الإدارة
5. **EPPC قبل النشر** — أي قاعدة سياق تمر بوابات Focus / Noise / Performance

---

## العلاقة مع Marketing Studio

```
Context Studio  →  يُنتج: السياق + الرسالة المناسبة + الأولوية
Marketing Studio →  يُنتج: مكان العرض + الجدولة + التفعيل
EHX              →  يُنتج: نبرة المحتوى + القيمة الإنسانية
EPPC             →  يوافق: هل العرض آمن للجودة؟
```

---

## التنفيذ المستقبلي (لم يُبدأ)

| مكوّن | الوصف |
|--------|--------|
| Context Rules Engine | قواعد IF سياق THEN رسالة/اقتراح |
| Admin — Context Studio | إدارة القواعد · المناسبات · قوالب الرسائل |
| API | `GET /api/core/context/home` (مقترح) |
| Integrations | وقت · طقس (اختياري) · تقويم مناسبات |

**لا يُبدأ Context Studio قبل استقرار M1 Marketing Engine** واجتياز validation EPPC للمرحلة الحالية.

---

## الشعار

> **Context Studio يفهم اللحظة. Marketing Studio يختار المسرح. EHX يختار الكلمات. EPPC يحمي التجربة.**
