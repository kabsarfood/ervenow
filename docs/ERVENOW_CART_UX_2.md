# ERVENOW CART UX 2.0

مرحلة واجهة المستخدم فقط — بدون تعديل Ledger أو Revenue Flow أو Checkout APIs أو منطق Unified Cart أو الحسابات المالية.

## الملفات المعدّلة

| الملف | التغيير |
|--------|---------|
| `public/assets/cart-ui.js` | هيكل HTML للسلة، استمرار التسوق، أكورديونات UX 2.0 |
| `public/assets/cart.js` | بطاقة منتج v2، صور، نصوص مطوية، فتح ملخص افتراضي |
| `public/assets/cart-luxe.css` | أنماط UX 2.0 (ذهبي، بطاقات، تقليل ازدحام) |
| `public/assets/cart-shell.css` | تمرير منتجات داخل الأكورديون المفتوح |
| `public/index.html` | نسخة السلة المضمّنة + `initLpHeaderCart` |
| `ervenow-frontend/assets/*` | مرآة للأصول أعلاه |
| `ervenow-frontend/index.html` | مرآة `index.html` |

## الهيكل (من الأعلى للأسفل)

1. **← استمرار التسوق** + عنوان **السلة**
2. **🛒 تفاصيل المنتجات** — مطوي: `عدد المنتجات (X)` · مفتوح: بطاقات المنتجات
3. **💰 ملخص المبالغ** — مطوي: `الإجمالي: XXX ر.س` · مفتوح: تفصيل المبالغ (ذهبي)
4. **💳 وسيلة الدفع** — مطوي: `💳 [الوسيلة]` · مفتوح: شبكة الوسائل الحالية
5. **إتمام الطلب** — زر ثابت + شارات الثقة

## قائمة التحسينات

- Accordion Layout متوافق مع المرجع البصري
- إزالة اللون الأحمر من ملخص المبالغ → **ذهبي / بني ملكي**
- نصوص ملخصة عند الطي لكل قسم
- بطاقة منتج أكبر: صورة (إن وُجدت في `data.image_url`)، متجر، متاح، كمية 44px، حذف
- **استمرار التسوق**: `sessionStorage.erv_cart_return_url` أو `history.back()`
- تقليل الحواف المكررة وشريط الإتمام المنفصل
- ملخص المبالغ يُفتح تلقائياً عند وجود منتجات (حتى يُغلقه المستخدم)
- زر **إتمام الطلب** بلون هوية ERVENOW

## نتائج الجوال (متوقعة)

- أزرار لمس ≥44px للكمية والحذف والأكورديون
- تمرير عمودي داخل قسم المنتجات فقط عند الفتح
- نصوص `clamp()` و`safe-area` على زر الإتمام
- لا تكبير iOS على عناصر التحكم (الكمية عبر أزرار)

## نتائج الكمبيوتر (متوقعة)

- لوحة سلة بعرض `min(600px, 100vw - 16px)` (portaled)
- أقسام مكدسة عمودياً مع فجوات 8px
- نفس الوظائف: دفع، محفظة EW PAY، عمولة، توصيل
