# فحص أخطاء Data API بعد RLS

فحص فقط في 2026-09-25. لا Migration ولا تعديل RLS.

## بعد إصلاح RLS

إصلاح RLS حوالي 12:40 بالتوقيت العالمي. سجل السيرفر المحلي بعد 12:35 لا يحتوي أي فشل Data API.

تنبيه 2.84% من 563 (نحو 16 فشلاً) يطابق نافذة استيقاظ المشروع قبل الإصلاح، من 12:09 إلى 12:31 بالتوقيت العالمي، وليس طلبات RLS.

## المتصفح وSupabase

لا يوجد `@supabase/supabase-js` ولا استدعاء `rest/v1` في صفحات المتصفح.
`createUserClient` معرّف في السيرفر وغير مستدعى.
قراءة `stores` و`withdraw_requests` تتم من مسارات السيرفر بصلاحية service_role.
لا مرجع تشغيلي لـ `order_number_counters`.
لا حاجة لإعادة فتح الجداول.

## مطابقة الملف مع القاعدة

`shared/migration_supabase_advisor_rls.sql` يطابق ما نُفّذ:
RLS على الجدولين، أربع سياسات رفض، والعرض `security_invoker=true`.
anon و authenticated بلا صلاحيات.
service_role يحتفظ بصلاحيات أوسع كانت موجودة قبل الملف، لأن الملف لم يسحبها.

## المسارات المرئية

الرئيسية عرضت متاجر (نسايم الشاورما وغيرها) بعد RLS عبر السيرفر.
صفحة المتاجر فتحت. لوحة التاجر أعادت التوجيه إلى تسجيل الدخول. الكاشير والمنتجات والطلبات والمندوب تحتاج جلسة ولم تُفتح بدون رمز واتساب.
