## 2. جدول المقارنة — قبل × بعد

> **تعريف «ارتفاع المحتوى قبل أول قسم رئيسي»:** المسافة من أعلى الصفحة (scrollY=0) إلى بداية القسم الرئيسي (`#homeHeroSection`، `#platformHeroSection`، أو `.guest-section-hero`).  
> **تعريف «عناصر أول شاشة»:** عدد الكتل المرئية في viewport (هيدر، أقسام، بطاقات، عناوين، أزرار CTA).

### 2.1 ملخص عام (متوسط الصفحات الست)

| العنصر | قبل الحذف | بعد الحذف | الفرق |
|--------|-----------|-----------|-------|
| **عدد العناصر في أول شاشة** (متوسط) | ~14–16 | ~13–15 | −1 إلى −2 (أقل ازدحاماً في الأعلى) |
| **ارتفاع المحتوى قبل أول قسم رئيسي** — جوال | ~286–425 px | ~125–283 px | **−161 إلى −263 px** |
| **ارتفاع المحتوى قبل أول قسم رئيسي** — سطح مكتب | ~576–621 px | ~64–190 px | **−386 إلى −557 px** |
| **عدد طلبات الشبكة** (متوسط) | ~28–32 | ~26–30 | **−2 إلى −3** (لا طلب `/api/core/banners` ولا صور بنر) |
| **حجم CSS المنقول** (متوسط) | ~87 KB | ~82 KB | **≈ −5 KB** (`banner-engine.css` لم يعد يُحمَّل) |
| **حجم JS المنقول** (متوسط) | ~148–155 KB | ~132–144 KB | **≈ −15–20 KB** (إزالة `banner-engine.js` + عدم جلب البنر) |
| **سرعة التحميل** (networkidle) | ~0.8–3.6 s | ~0.6–3.6 s* | أسرع قليلاً على الصفحات التي كانت تعرض بنراً ثقيلاً |
| **تجربة الجوال** | هيدر + بنر يستهلك ~40–50% من الشاشة قبل المحتوى | الهيدر + بطاقة/عنوان مباشرة | **وصول أسرع للمحتوى** |

\* الرئيسية على الجوال (أول تحميل بارد) ~2.5 s — باقي الصفحات ~0.6–1.4 s.

## 3. تقييم تجربة المستخدم

### 3.1 الصفحة الرئيسية

| السؤال | التقييم |
|--------|---------|
| **هل أصبحت أبسط؟** | **نعم.** اختفى الشريط الإعلاني المزدحم (نص مدمج في الصورة + CTA مكرر). المسار البصري: هيدر → بطاقة «اطلب أي خدمة» → الأقسام. |
| **هل أصبحت أسرع؟** | **نعم، perceptually.** وصول البطاقة الرئيسية أسرع بـ **~263px جوال / ~450px سطح مكتب**. لا انتظار دوران شرائح ولا تحميل صور بنر 1920×730. |
| **هل أصبحت فارغة أكثر من اللازم؟** | **لا على الجوال** — بطاقة Hero (~430px) تملأ معظم الشاشة الأولى. **على سطح المكتب** قد يُشعر بفراغ جانبي (البطاقة ~506px عرضاً) لكن ليس «فارغة» عمودياً. |
| **فراغ بصري يحتاج معالجة؟** | **خفيف:** بين بطاقة Hero وموجة الأقسام — مقبول. **لا حاجة لبنر جديد**؛ البطاقة الحالية (بعد تحسين الارتفاع) تؤدي دور «الفخامة» أفضل من البنر القديم. |

### 3.2 لوحة الزائر

| السؤال | التقييم |
|--------|---------|
| **هل اختفى التكرار السابق؟** | **نعم — تحسّن واضح.** سابقاً: بنر Hero (صورة ترحيب) + بطاقة «مرحباً بك» + عروض. الآن: **تنبيه زائر → ترحيب → عروض → تبويبات**. |
| **هل أصبحت العروض أوضح؟** | **نعم.** `#guestOffersCarousel` أصبح العنصر البصري الأقوى بعد بطاقة الترحيب مباشرة (416px على سطح المكتب). |
| **هل بداية الصفحة أفضل؟** | **نعم على سطح المكتب** (توفير ~386px). **على الجوال** الفرق طفيف (~3px) لأن بطاقة الترحيب وشريط الزائر كانا يoccupون المساحة؛ لكن إزالة البنر أزالت تشتيتاً بصرياً. |

### 3.3 المطاعم · المتاجر · الخدمات · التوصيل

| السؤال | التقييم |
|--------|---------|
| **وصول أسرع للمحتوى؟** | **نعم — خاصة سطح المكتب** (−512px). المستخدم يرى العنوان + البحث + التصنيفات فوراً. |
| **اختفت مساحات غير ضرورية؟** | **نعم.** الشرائح الافتراضية/الإدارية (1920/730) كانت تكراراً لعنوان `.guest-section-hero` النصي تحتها. |
| **فراغ كبير في الأعلى؟** | **لا على الجوال.** **على سurface المكتب:** فراغ أقل من قبل — كان البنر يشغل نصف الشاشة تقريباً؛ الآن عنوان مضغوط (~135px) ثم المحتوى. **صفحة التوصيل:** لا يوجد `.guest-section-hero` — المحتوى يبدأ مباشرة بعد الهيدر (مقبول). |

## 4. توصيات فقط (بدون تنفيذ)

### ماذا نُبقي؟

1. **بنرات العروض** (`#guestOffersCarousel` + `/api/core/platform-offers`) — العنصر الترويجي الوحيد المثبت قيمته.
2. **بطاقة «اطلب أي خدمة الآن»** في الرئيسية — بديل أقوى من البنر القديم من حيث الوضوح والهوية.
3. **`.guest-section-hero`** في صفحات الأقسام — عنوان + وصف كافٍ دون بنر صورة.
4. **بطاقة الترحيب** في لوحة الزائر — مع **العروض** تحتها مباشرة.

### ماذا نُحسّن؟ (CSS/محتوى فقط — لا بنرات Hero جديدة)

1. **لوحة الزائر — جوال:** دمج أو تقليل المسافة بين «تنبيه الزائر» وبطاقة الترحيب لتقريب العروض من أعلى الشاشة.
2. **الرئيسية — سطح مكتب:** توسيع عرض بطاقة Hero قليلاً (بحد أقصى ~900px) لتقليل الفراغ الجانبي — **ليس بنراً جديداً**.
3. **الأقسام:** إضافة صف «اختصارات» (chips) مباشرة تحت العنوان إن رُئي أن المنطقة «جافة» — بدون carousel.
4. **الأدمن:** إخفاء أو أرشفة «إدارة البنرات V2» لتجنب لبس الفريق (البنرات لا تُعرض على الواجهة).

### هل نحتاج بنرات Hero مستقبلاً؟

**التوصية: لا — في الوضع الحالي.**

| السبب | التفصيل |
|-------|---------|
| تكرار | البنر كان يكرر عنواناً أو CTA موجوداً في بطاقة Hero أو `.guest-section-hero`. |
| جودة | صور الأدمن كانت مزدحمة؛ العروض (`guest-offers`) أوضح بصرياً. |
| أداء | كل صفحة كانت تدفع طلب API + CSS/JS + صور إضافية. |
| جوال | البنر + الهيدر كانا يؤخران الوصول للمحتوى ~19% من viewport. |

### هل بنرات العروض الحالية كافية؟

**نعم — كطبقة ترويجية وحيدة.**

- مرتبطة بمنتجات/أسعار حقيقية (عكس بنرات Hero العامة).
- موضعها في لوحة الزائر منطقي (بعد الترحيب، قبل التبويبات).
- **اختياري لاحقاً:** نسخة مصغرة من شريط العروض في الرئيسية **فقط إن رُصدت حاجة تسويقية** — ليس بنر Hero بمقاس 1920×730.
