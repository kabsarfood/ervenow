ERVENOW — خريطة التسجيل مقابل Checkout (تحليل فقط)
التاريخ: 2026-09-22
لم يُغيَّر Login أو Checkout أو الطلبات أو الدفع.

مساران لا يختلطان
أ) /login إنشاء عضوية: OTP → نوع → فئة → بيانات خفيفة → إنشاء
ب) ضيف يتسوق: تصفح وسلة بلا حساب → عند تأكيد الطلب والدفع فقط OTP → Customer تلقائي إن كان الرقم جديدًا

1) فئات المطاعم (restaurantCategories + /api/categories)
كبسة وبخاري · شاورما ومشاوي · سمك · برقر · بروستد · بيتزا · مقاهي · حلويات · أسر منتجة
لا يوجد slug «سعودي» أو «وجبات سريعة». الخلفية: stores.type=restaurant و role=store. المستخدم يرى مطعم.

2) فئات المتاجر (stores.type)
سوبرماركت · ميني ماركت · صيدلية · تجميل وعناية · ورود وهدايا · ملابس · خضار · ملحمة · بيع أسماك · حلويات (متجر) · أسرة منتجة · غيره
أقسام المنتجات داخل السوبرماركت/الملابس ليست فئات تسجيل. إلكترونيات ومستلزمات منزلية غير موجودة اليوم.

3) فئات الخدمات (service_type)
سباك · كهربائي · مكيفات · غسيل/تنظيف · مهندس زراعي · تلميع مركبات · تبديل غاز · تعبئة غاز مركزي
Role=service. غاز حساب خدمة رغم ظهوره للعميل تحت التوصيل.

4) التوصيل والنقل
لا role=transport.
مندوب: role=driver + مركبة car/bike
طرود/توصيل داخلي: internal_delivery (البوابة الحالية Driver)
سطحة: pickup_truck → service → transport-preview
نقل أثاث: furniture_move → service → transport-preview
دباب/سيارة/ونيت: فئة مركبة على الطلب وليست Role.

5) ربط البطاقات الخمس
عميل → customer → /
مطعم → store + type=restaurant + category من API → merchant-preview
متجر → store + type من قائمة المتاجر → merchant-preview
خدمات → service + service_type (بدون نقل/مندوب) → service-preview
التوصيل والنقل → مندوب=driver أو نقل=service+type. لا role=transport جديدة.

6) ملتبس — يحتاج قرارك
غاز: تسجيل خدمات / اكتشاف توصيل
حلويات: مطعم sweets vs متجر sweets
أسر منتجة: home_producers vs home_business
بيع أسماك vs مطاعم سمك
تلميع: خدمات
إلكترونيات/منزلية: غير موجودة
دباب/سيارة: تحت مندوب كنوع مركبة
stores.type=services: لا يُعرض في بطاقة المتجر

7) /login لاحقًا (لم يُنفَّذ)
خمس بطاقات بعد OTP لإنشاء العضوية فقط
الفئات في الخطوة التالية من المصادر الحالية لا قائمة جديدة
بيانات خفيفة؛ الثقيل داخل البوابة
لا فتح register-store الثقيل كبوابة مستقلة في هذه المرحلة

8) Checkout لاحقًا (لم يُنفَّذ)
اليوم تأكيد الطلب بلا توكن → /login?mode=register&role=customer فيُفتح اختيار العضوية للرقم الجديد (خلط المسارين)
المطلوب: OTP سياق checkout → موجود=ربط · جديد=Customer تلقائي بلا بطاقات
قبل OTP: Draft فقط. بعد OTP+تأكيد: Order تنفيذي. لا طلب وهمي للتاجر/المندوب/المزود.
PUBLIC_ORDERING كان معطّلًا على الخادم الحي (pre-registration) — يُراعى عند التنفيذ لا الآن.

لا تنفيذ حتى تعتمد الخريطة وقرارات البند 6.
